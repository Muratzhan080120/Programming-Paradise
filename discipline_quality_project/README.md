# Система оценки качества дисциплины

Мини-проект по теме 11 курса «Парадигмы программирования»: анонимный сбор и анализ ответов студентов по шкале 1–5.

## Возможности

- проверка оценок: допустимы целые числа от 1 до 5;
- обнаружение неполных анкет и исключение их из основного рейтинга;
- расчёт средних значений и медиан по вопросам;
- выявление проблемных вопросов по доле оценок 1–2;
- сравнение двух агрегаторов: среднего арифметического и медианы;
- импорт ответов из CSV и экспорт сводной статистики;
- консольное меню и автоматические тесты.

**Важно об анонимности:** пример не хранит имена студентов. `respondent_id` — техническая метка тестовой записи, необходимая для различения строк; в реальном опросе не следует связывать её с личностью студента.

## Требования

- Python 3.10 или новее
- Дополнительные библиотеки не нужны

## Формат данных

`data/responses.csv` содержит `respondent_id` и столбцы `q1`–`q5`. Значение от 1 до 5 — оценка; пустая ячейка — пропуск. Демоданные синтетические, это не реальные ответы студентов.

## Как определяется проблемный вопрос

Для каждого вопроса считается доля оценок 1 и 2. По умолчанию вопрос отмечается как проблемный, если доля таких оценок не меньше 35%. Порог передаётся параметром и может быть изменён.

## Применение лекций 1–8

| Лекция | Реализация в проекте |
|---|---|
| 1. Парадигмы | Сравнение процедурного подхода и объектной модели; сравнение среднего и медианы |
| 2. Императивная | Циклы, ветвления и состояние консольного меню в `main.py` |
| 3. Процедурная | Функции проверки, загрузки, анализа и форматирования |
| 4. Структурная и модульная | Разделение моделей, агрегаторов, логики, сервиса и точки входа |
| 5. ООП | `Survey`, `Response`, `QuestionStats`, `SurveyReport`; неизменяемые dataclass-модели |
| 6. Интерфейсы и полиморфизм | Абстрактный `Aggregator`, реализации `MeanAggregator` и `MedianAggregator`; сервис принимает любой агрегатор |
| 7. Функциональная | Чистые функции фильтрации и расчёта, неизменение входных коллекций, `recursive_count` |
| 8. Функции высшего порядка | `filter`, `reduce`, генератор предиката `make_threshold_filter` |

## Сравнение подходов

**Процедурный вариант:** напрямую вычислять сумму и количество оценок в одной функции. Он прост, но при добавлении медианы и других способов расчёта функция разрастается.

**Объектный вариант со стратегией:** `Aggregator` задаёт общий интерфейс, а `MeanAggregator` и `MedianAggregator` реализуют разные способы расчёта. Сервису не нужно знать детали вычисления: можно заменить стратегию без изменения отчётного кода.

## Ограничения и дальнейшее развитие

Это учебный прототип: данные читаются из CSV, интерфейс консольный, анонимность обеспечивается отсутствием имён в демонстрационном наборе. Для реального использования потребуются защищённое хранение, контроль доступа, согласование формулировок опроса и политика хранения данных.
